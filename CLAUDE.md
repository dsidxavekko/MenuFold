# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MenuFold is a macOS (26+, developed on macOS 27) SwiftUI app that replaces the Dock "Applications" stack. It is pinned in the Dock like a normal app. Clicking its icon opens a borderless panel centered on the screen, holding a grid of all apps with user-made folders (one level deep, made by drag-and-drop), automatic category tabs and search. It does not patch the Dock or any system process (no SIP changes). UI is localized in Ukrainian and English (see Localization below). Distributed through GitHub Releases (DMG + Sparkle updates); there is no sandbox and signing is ad-hoc.

## Commands

```bash
# Logic package: build + tests (works with Command Line Tools only, no Xcode needed)
cd Packages/MenuFoldCore && swift build && swift test
swift test --filter GridModelTests                 # one suite
swift test --filter "GridModelTests/previewModel"  # one test

# App (needs full Xcode at /Applications/Xcode.app + `brew install xcodegen`)
scripts/build.sh        # xcodegen generate + xcodebuild into ./build
scripts/build.sh run    # same, then kill the running copy and open the new one
```

- `MenuFold.xcodeproj` is generated from `project.yml` and gitignored. Edit `project.yml`, never the project. Re-run `xcodegen generate` after adding or removing files.
- `scripts/build.sh` sets `DEVELOPER_DIR` to Xcode by itself when `xcode-select` still points at Command Line Tools, so `sudo xcode-select` is not required.
- `scripts/typecheck-app.sh` typechecks `App/` in about 5 s against the built package (it builds `MenuFoldCore` first), without building or signing the app. With Xcode installed it checks the real sources; without Xcode it checks a scratch copy with stand-ins for the Xcode-only macros (`@State`, `@Entry`) and `#Preview` wrapped in `#if canImport(XcodeSupport)`, using `-parse-as-library -warnings-as-errors`. CI runs it, so App/ changes are checked even when nobody has Xcode.
- Tests use Swift Testing, not XCTest (XCTest is missing on CLT). `Package.swift` adds a `-plugin-path` flag to the test target only when CLT is the selected developer dir. Leave that block alone.
- Without Xcode, `swiftc -typecheck` on `App/` fails on `@State`, `@Entry` and `#Preview`. On this SDK all three are macros whose plugins (SwiftUIMacros, PreviewsMacros) come only with Xcode. `scripts/typecheck-app.sh` handles that fallback; it is the supported way to check `App/` without Xcode (do not hand-roll another scratch copy).

## Architecture

There are two layers. Only the package is unit-tested.

**`Packages/MenuFoldCore`** holds all logic and has no views. Its public API was the contract that the app layer was written against, so keep signatures stable.
- `AppCatalog.swift`: `AppCatalogProviding`. `SpotlightAppCatalog` runs an `NSMetadataQuery` for `com.apple.application-bundle` and reads Info.plists off the main thread. It publishes `apps` and calls `onChange` on the main actor, only when the list changed, debounced about 0.3 s after the first scan. `StaticAppCatalog` serves previews and tests.
- `AppFilter.swift`: a pure `filter([AppCandidate]) -> [AppEntry]` that holds all the "which apps to show" rules, and it has tests:
  - It drops apps nested in any bundle (`.app`, `.framework`, `.xpc`, …).
  - It drops everything under `/System/Library`, `/Library` and `~/Library`, except Finder and `CoreServices/Applications/*`.
  - It de-duplicates by bundle ID, preferring `/Applications`, then `/System/Applications`, then `~/Applications`, then the newest copy.
  - It removes MenuFold itself.
- `Layout.swift` / `LayoutStore.swift`: the persisted state is folders (bundle-ID lists, colour, optional SF Symbol), category overrides, custom categories and hidden IDs. It is saved as JSON at `~/Library/Application Support/MenuFold/layout.json` with atomic writes. Decoding has two levels of leniency: a missing key keeps its default (old/newer files load), but a key that is present with the wrong shape is corruption. A missing file gives an empty layout. A file that can't be decoded, or that comes from a newer app version (`version > Layout.currentVersion`), is moved aside to `layout.corrupt-<date>.json` and `GridModel` immediately writes a fresh layout, so the next launch has a valid file; `GridModel.layoutOutcome` / `LayoutStore.lastQuarantineFailed` tell Settings to warn. A file that can't be *read* (permissions, lock, I/O) is left untouched and retried next launch. Load-time validation drops duplicate folder ids, manual folders with fewer than two apps, and finder paths with dot segments.
- `CustomIcons.swift` + `GridModel.setCustomIcon(for:from:)` / `resetCustomIcon(for:)`: a user icon for an app. The picked file (any image, or another app/file whose Finder icon is used) is rendered to a 512 px PNG with a fresh UUID name in `LayoutStore.iconsDirectory` (`…/MenuFold/Icons`); `Layout.customIcons` maps bundle ID → file name (kept for uninstalled apps). Unused files are deleted on reset and on a launch that really loaded the layout (never after a quarantine). App side: `IconCache.icon(for: AppEntry)` / `icon(appID:url:)` prefers the custom file; `CustomIconPicker` opens the `NSOpenPanel` from the tile menu and Settings → Програми.
- `GridModel.swift`: the `@MainActor @Observable` hub. It merges catalog and layout into `GridItem`s for the current `tab` and `query`. Every mutating intent saves right away. Rules:
  - A folder left with ≤1 app is dissolved.
  - Folders keep the IDs of uninstalled apps, so an app goes back into its folder after reinstall. A folder with no visible apps is not shown.
  - A non-empty search ignores the tab and finds apps inside folders too.
  - Category tabs are flat lists that ignore folders.
  - "Запущені" (`GridTab.running`) is a flat list of `runningAppIDs`, which the app feeds from `RunningAppsMonitor`. It sits right after "Все", is not reorderable, and `showsRunningTab` (Settings → Категорії, default on in the app, off in the model) hides it.
  - Custom categories (`Layout.customCategories`, ids prefixed `custom.`) are user-made tabs. Apps join one through `categoryOverrides`. Their tabs come right after "Все" and show even when empty. Deleting one drops its overrides, so its apps go back to their automatic category. They are created from the tile menu ("Нова категорія…", then renamed inline on the tab via `renamingCategoryID`), renamed or deleted from the tab's context menu, and managed in Settings.
  - Tab order: `Layout.categoryOrder` holds category ids (system or custom) in the user's order; categories not in it follow in the default order (custom, then system by name, "Інше" last). "Все" is always first. Tabs are reordered by dragging in the panel or "Пересунути ліворуч/праворуч" in the tab's context menu; Settings can reset the order.
  - `GridModel.preview` is the sample model every `#Preview` uses.
  - Search (`GridModel+Search.swift`, `SearchMatcher.swift`): ranked, not alphabetical (exact > prefix > word prefix > initials > substring > fuzzy, ties by usage). A query typed in the wrong keyboard layout (ЙЦУКЕН ↔ QWERTY) matches too. Matching folders come as folder items; `matchingTabs` feeds the tab chips; `settingsPaneResults` (`SystemSettingsPanes.swift`, ≥2 characters) opens System Settings panes. Selection ids: "pane:<id>".
  - `GridModel+Arrange.swift`: pinned apps (`Layout.pinned`, "Закріплені" row on "Все", selection ids "pinned:<id>", left out of "Часті"); manual order of "Все" (`Layout.manualOrder` of `GridItem.id`s, nil = alphabetical; a new folder takes the target app's place); "Недавні" (`GridTab.recent`, from `history.lastLaunched`); undo/redo of layout changes (in memory, 50 steps; every `commitPersisting` records one unless `isRestoringUndo`; restoring keeps the current `customIcons`, because icon files may be gone); `selectTab(at:)`/`cycleTab(by:)`; Dock-menu helpers.
  - `KnownAppCategories.swift`: `AppCategory.automatic(for:)` — Info.plist category, else a table of well-known bundle ids and prefixes, else "Інше".
  - `GridModel+Data.swift` + `AppHistory.swift`: `history.json` (first-seen and last-launched dates, never decays) behind new-app dots (`isNew`) and the unused-apps list; daily `Backups/layout-yyyyMMdd.json` (7 kept, restorable, undoable); export/import (`LayoutTransfer.swift`: layout + icons as base64, validated like layout.json); `reloadLayoutFromDisk()` for a synced data folder; uninstaller leftovers (`AppLeftovers.swift`: only files that unmistakably belong to the bundle id in ~/Library, never `com.apple.*`; `moveToTrash(_:leftovers:)` re-checks every URL).
- `FinderFolders.swift` covers Finder folders. A real subfolder of `/Applications` or `~/Applications` (keyed by its top-level folder), as well as `/System/Applications/Utilities`, is shown as a folder:
  - It is one-way and read-only, so MenuFold never moves files.
  - These folders are synthesized on every query (`Folder.finderPath != nil`, with a stable id derived from the path) and are never stored in `layout.folders`.
  - Manual folders win.
  - `rename` does nothing on them. `add` (an app dropped onto the tile) is virtual: it goes to `finderAdditions` (bundle ID → path), which beats the real location and exclusions. `dissolve` goes to `ignoredFinderFolders`. Pulling an app out removes its addition, or goes to `finderExclusions` if the app really lives in a Finder folder. Colours live in `finderStyles`.

**`App/`** is the AppKit + SwiftUI shell.
- `AppPreferences.swift`: app-level switches in UserDefaults (`@Observable`, posts `.menuFoldPreferencesChanged`): global hotkey, menu bar icon, keep-panel-open, remember last tab, "Недавні"/pinned/folder counts/new dots, grid columns × rows (`GridMetrics` computes the panel size from them), first-run hint, data folder. `AppDelegate.applyPreferences` copies the model switches into `GridModel`.
- Ways to open the panel besides the Dock: `HotKeyManager` (Carbon `RegisterEventHotKey`, no permissions), `StatusItemController` (menu bar), `URLCommandHandler` (`menufold://toggle|show|hide|search?q=|folder?name=|tab?name=|settings`), `MenuFoldIntents.swift` (Shortcuts). `AppMenus.swift` builds the Dock/menu-bar menu (pinned and most-used apps, folders with "Відкрити всі", update item).
- Data folder: layout.json and Icons/ live in `AppPreferences.layoutFileURL` (default `~/Library/Application Support/MenuFold`, or a synced folder chosen in Settings → Дані; applied after `AppDelegate.relaunch()`). A chosen folder X becomes `X/MenuFold/`; changing it requires a restart. `LayoutStore.isShared` is set for it, which turns off destructive housekeeping (no fresh empty layout after a quarantine, no icon-file cleanup), since another Mac may still use that data. `LayoutFileWatcher` calls `reloadLayoutFromDisk()` when another Mac changes it; a reload applies without saving and clears undo/redo. usage.json and history.json stay in the default folder unless a data folder is chosen; then they live there and are merged between Macs (see Statistics below). usage-log.json always stays in the default folder.
- `MenuFoldApp.swift`: `AppDelegate` owns the single `GridModel` and `PanelController`, and keeps them alive for the app's lifetime. A Dock click arrives as `applicationShouldHandleReopen` and toggles the panel. The panel is also shown on launch. `model.onLaunched` hides the panel.
- `PanelController.swift`: a borderless key-capable `NSPanel`. It draws the window chrome as an AppKit `NSGlassEffectView` (Liquid Glass, `Theme.panelCorner`) hosting the SwiftUI root, and it runs the open/close scale+blur animation with Core Animation on the glass layer. The views must not draw their own background. It hides on resign-key, Esc, app launch or a second Dock click. A 0.3 s guard stops the hide-then-reopen flicker from Dock clicks. Esc closes an open folder first, then the panel.
- `DockGeometry.swift`: the anchor is `NSEvent.mouseLocation` at the moment of the Dock click, so no Accessibility permission is needed. The panel is always centered on that screen; the user prefers this over sitting above the icon. `isNearDock` uses the Dock orientation (bottom, left or right), `tilesize` and magnification from `com.apple.dock` defaults, because auto-hide reserves no space in `visibleFrame`, and confirms with the Dock's window frames from CGWindowList. It only drives the reopen guard.
- Keyboard: `PanelController` has a local `keyDown` monitor (the search field swallows SwiftUI `onKeyPress`). ↑/↓ always move `model.selectedItemID`; ←/→ and Return only when something is selected (otherwise they go to the search field, whose Enter launches the first app); ⌘R reveals, ⌘⌫ asks to trash, ⌘1…⌘9 and ⌃Tab/⌃⇧Tab switch tabs, ⌘Z/⇧⌘Z undo/redo layout changes (only with an empty query; otherwise the text field's own undo). It stands aside during inline renames (category tab, folder title). Mouse hover never changes the selection. Tiles show it as the hover lift plus an accent ring (`Theme.selectionRing*`), and `GridView`/`FolderOverlayView` scroll to it.
- "Часті" row: `model.frequentApps` above the grid on "Все" with no query (tiles use `GridModel.frequentSelectionID`, never make folders). `AppDelegate` records every launch via `NSWorkspace.didLaunchApplicationNotification` and keeps the `showsFrequent` switch in UserDefaults (`AppDelegate.showsFrequentKey`).
- `RunningAppsMonitor.shared`: running bundle IDs (KVO on `NSWorkspace.runningApplications`) for the Dock-like dot under a tile, the "Завершити" menu items and the trash card.
- Trash: the tile menu / ⌘⌫ only set `model.pendingTrashAppID`; `TrashConfirmationCard` (drawn by `MenuFoldRootView` over a dim, modal) asks, offers to quit a running app first, offers to remove the app's support files too (looked up off the main actor) and shows failures. Return reaches it as `.menuFoldTrashConfirm` from the key monitor; Esc and a click outside cancel.
- `IconCache.shared.icon(for:)`: the only place where icons are loaded, and it caches them. Views call it from `body` with the `AppEntry` (not the URL), so custom icons apply.
- `Views/`: `MenuFoldRootView(model:)` (fixed 844×577 like the system Apps launcher, see `GridMetrics`; transparent) contains `SearchField`, `CategoryTabs`, `GridView`, `FolderOverlayView` (iPhone-style expanded folder with an editable title), and the tiles together with their context menus. Tiles drag via an AppKit `NSDraggingSource` (`AppDragSource.swift`). The pasteboard holds the file URL plus the private `com.menufold.app-id`. Outside the app only `.link` is allowed (Finder makes an alias, never a move or copy), with `.generic` added only over the Dock for pinning. Internal drops accept only the private types; the one exception is files from outside on an app tile (`TileFileOpening`: opens them with that app, never executable types, none when more than 20 files). Folder-making drops are enabled only on the "Все" tab with an empty query. `MenuFoldCore.GridItem` clashes with `SwiftUI.GridItem`, so write out the full name.

Styling is Liquid Glass (macOS 26 APIs used directly, with no `#available`). All motion and shape constants live in `App/Views/Theme.swift`, so reuse them. Every animation has a Reduce Motion fallback.

Any separate window or sheet opened from the panel takes key status and closes the panel. Put new UI inside the panel or in the Settings window. The panel has no settings button: Settings open from the app menu (⌘,, "Про MenuFold") or the Dock icon's menu (`applicationDockMenu`). Settings is an AppKit window with toolbar tabs (`SettingsWindowController`, `SettingsTab`: Загальне, Вигляд, Категорії, Програми, Дані, Статистика, Про програму), opened with `AppDelegate.showSettings(tab:)`. Do not go back to the SwiftUI `Settings` scene for it: it cannot be opened from code (`showSettingsWindow:` is ignored with "Please use SettingsLink"). Debug builds accept `--args -openSettings <tab>` to open a tab on launch.

Distribution: `scripts/release.sh` builds the Release app and writes `dist/MenuFold-<v>.dmg` (for people), `dist/MenuFold-<v>-macos26-arm64.zip` (what Sparkle downloads), `dist/appcast.xml` (one item, the EdDSA signature of the zip) and the `CHANGELOG.md` section of that version as `dist/release-notes.md`. `CFBundleVersion` is the commit count of HEAD, set by the script (Sparkle compares it), so `CURRENT_PROJECT_VERSION` in `project.yml` only matters for Debug. Signing stays ad-hoc (no Apple Developer account); updates are trusted through `SUPublicEDKey` in `Info.plist`. The private key is in the maintainer's login Keychain (Sparkle `generate_keys`) and in the `SPARKLE_PRIVATE_KEY` repo secret for the Release workflow; never regenerate it, or installed copies stop accepting updates. `SUFeedURL` is `releases/latest/download/appcast.xml`. `App/Updater.swift` wraps `SPUStandardUpdaterController` (menu "Перевірити оновлення…", Dock menu, Settings → Загальне → Оновлення); Debug builds don't start it unless run with `--args -enableUpdates YES`. It uses `#if canImport(Sparkle)` because `scripts/typecheck-app.sh` only finds Sparkle after an xcodebuild has fetched it. `App/InstallLocation.swift` offers to copy the app from a mounted DMG into /Applications on launch, and explains moving it when macOS runs a translocated copy.

Localization: UI strings are keyed by their Ukrainian text in `App/Localizable.xcstrings` (source language `uk`, plus `en`, `de`, `pl`, `fr`, `es`). Literals passed to SwiftUI `Text`/`Button`/`Label`… are localized automatically; any text that travels as a `String` (ternaries, enum titles, `NSMenuItem`, `NSAlert`, `EmptyStateView`) must use `String(localized:)`. `MenuFoldCore` strings go through `L(_:)` (`Localization.swift`, looks up the app's catalog; tests get the key back) and are marked `manual` in the catalog. Every new key needs a translation into every language of the catalog. `CFBundleDevelopmentRegion` is `en`, so other system languages fall back to English. App names follow the *system* language list (global `AppleLanguages`), not MenuFold's UI language: `BundleReader.localizedName` reads `InfoPlist.loctable` or `<lang>.lproj/InfoPlist.strings`; the unlocalized name is kept as `AppEntry.alternateName` and search matches both.

App icon: the source is `Design/AppIcon.svg`; `scripts/render-icon.sh` renders it (headless Chrome) into every PNG of `App/Assets.xcassets/AppIcon.appiconset`. Never edit the PNGs by hand. The Dock icon can be switched in Settings (`DockIconStyle`: MenuFold logo, the macOS launcher `Apps.app` (offered only when installed), the system Applications folder icon, or the user's own picture stored as `…/MenuFold/DockIcon.png`, outside `Icons/` so the app-icon cleanup never deletes it). It is applied at runtime (`NSApp.applicationIconImage`) and also written as a Finder custom icon onto the .app bundle (`NSWorkspace.setIcon`), so the Dock keeps it while MenuFold is closed. macOS App Management may refuse the bundle write; Settings then says so. An update replaces the bundle, so launch re-writes the custom icon.

## 0.6 additions

Details of the 0.6 features, by area.

### Search
Search internals: `SearchMatcher.Target` (names, keywords, bundle ID) is folded once per catalog change (`GridModel.searchTargetsCache`); keywords/bundle ID score below every name tier (`metadataScore`; ≥3 letters keywords, ≥4 or a dot for IDs; direct typing only). Synonyms: `AppCategory.categorySynonyms`, `KnownApps.kindKeywords` (KnownAppCategories.swift). `GridModel` caches `appsByID`, `visibleApps`, `finderFolders` (dropped in `apps`/`layout` didSet via `invalidateDerivedCaches`). `lastSearchMatch` narrows the next keystroke when the new query extends the old one (old ≥4 chars; sparse fuzzy matches that appear only with a longer query can be missed). `KeyboardLayout.shouldConvert` skips layout swap for digits, non-key symbols and a dot inside a Latin word. Prefix scopes: `GridModel.parseSearch` / `SearchScope` (`>` `/` `@cat rest` `?`); prefix queries hide tab chips. Adaptive ranking: `SearchChoices` (`search-choices.json` beside usage.json, ≤300 queries, bonus ≤12 clamped inside the match tier), recorded in `GridModel.launch` via `rememberSearchChoice`; usage adds ≤6 the same way.

### Smart categories and profiles
- Smart categories (`SmartRules.swift`, `Layout.smartRules`, ids prefixed `smart.`): `SmartRule` = AND of set criteria (bundle-ID prefixes, `AppEntry.installSource`, `minSizeMB` via `GridModel.appSizes`, `unusedDays` via `history.lastLaunched` else Spotlight date; unknown values never match). `GridModel.category(of:)` returns the first matching rule after a manual `categoryOverrides` entry and before the automatic category. Tabs (`smartCategories`) sit after custom ones and only show while non-empty. `AppInstallSource` is read off the main thread: `BundleReader.installSource` (`Contents/_MASReceipt/receipt`, Setapp path/prefix) and `BundleReader.homebrewCaskAppNames()` (Caskroom scan) in the catalog's detached task; sizes are measured by `GridModel.refreshAppSizes()` (detached walk, cached per path, only when a rule uses a size). UI: `ProfilesSettingsView.swift` (`SmartRulesSection`).
- Profiles (`Profiles.swift`, `Layout.profiles`, `Layout.activeProfileID`): `Profile` = extra `hidden`, own `pinned` (after global pins in the row), optional `visibleCategories` (apps of other categories and their tabs are left out). The filter lives in `visibleApps` (`profileAllows`). API: `profiles`, `profileNames`, `activeProfile`, `setActiveProfile(_ id:)`, `setActiveProfile(named:) -> Bool`, `createProfile/updateProfile/deleteProfile`. Switching commits with `isRestoringUndo` so it is NOT an undo step; undo/redo keep the current profile (`Layout.keepingActiveProfile(of:)`). Dock/menu-bar menu has a "Профіль" submenu (`menuSetProfile`); `menufold://profile?name=` (empty or "none" = no profile).

### Quick actions and info card
Quick actions (`GridModel+KeyActions.swift`): `togglePinOnSelection`, `moveSelectedTile(_:columns:)` (manual order of "Все" via `moveItem`, or `movePinned` in the pinned row), `launchNewInstanceOfSelection`, `revealSelectionInFinder`, `showInfoForSelection`. `PanelController.handleQuickAction` maps them to ⌘D, ⌥+arrows, ⌥Return, ⇧Return, ⌘I and ⌘/ (`GridModel.showsShortcutsHelp`). `AppInfo.swift` + `GridModel.appInfo(for:)` read bundle facts off the main actor for `AppInfoCard` (`GridModel.infoAppID`, drawn by `MenuFoldRootView` like the trash card; Esc/Return/click outside close it). `AppHistory.launchCounts` (bumped in `noteLaunched`) feeds the launch count. `ShortcutsHelp.swift` holds `PanelShortcuts` (the list shown by ⌘/ and in Settings -> Загальне). Core string "Система" (AppInfo.Source) must be marked manual in the catalog.

### Drag and drop
Drag and drop: `AppDragSession` also tracks folder drags (`folderItemID`, `isDragging`). `FolderDragSourceView` (AppDragSource.swift) drags a folder tile with only the private type `com.menufold.folder-id` (declared in Info.plist, `GridItem.id` payload, empty operation mask outside the app, so it never leaves MenuFold); `TileDropDelegate` accepts it on the edges of other tiles and calls `GridModel.moveItem`. The same delegate takes files from outside on an app tile (`TileFileOpening`: only when `urlsForApplications(toOpen:)` lists the app; `NSWorkspace.open(_:withApplicationAt:)`) and does spring-loading (`SpringLoad`, `Theme.springLoadDelay`, an app held 0.8 s over a folder opens it). The "Закріплені" row reorders by dropping on tile edges (`GridModel.movePinned(_:before:)` / `movePinned(_:after:)`; an unpinned app dropped there is pinned at that place). Dropping a tile on a category tab (`setCategory`) was already in CategoryTabs.

### Emoji folders and persistent undo
Emoji folder icon: `FolderEmoji` (Core) validates exactly one emoji grapheme; `GridModel.setFolderEmoji(folder:to:)` stores it as `Folder.symbol = "emoji:<text>"`. `FolderOverlayView` has an inline emoji button/row (quick emoji + text field), no popover.

Persistent undo (`UndoPersistence.swift`): `undo.json` (LZFSE-compressed JSON: `current` layout + last 10 undo layouts) next to layout.json. Written from `commitPersisting`; restored once after a real layout load only if `current` equals the loaded layout (else ignored). Never written/read when `LayoutStore.isShared`; reloadLayoutFromDisk does not touch it. Icon cleanup keeps files named by restored undo steps. Redo is not persisted.

### Storage
Storage: `LayoutStore` checks the file size (`FileManager.attributesOfItem`, not URL.resourceValues, which caches) before reading (`LayoutStore.readLimited`, `LayoutTransfer.decode(contentsOf:)`). `save` retries a failed quarantine each time and rotates `layout.bak`/`layout.bak2` (copy of the previous valid file; first save of a session, then at most every 10 min; skipped for `isShared`); after a quarantine only the 5 newest `layout.corrupt-*` remain (not for `isShared`). `LayoutTransfer.installIcons` re-encodes every icon to PNG ≤512 px, limits: 1000 icons, 8 MB and 4096 px each.
Layout migration: `Layout.migrations[n]` upgrades version n to n+1; `Layout.migrated()` runs in `LayoutStore.validated` and on load. Bump `currentVersion` and add a step only for changes that a new optional key cannot express.
`FinderFolders.bundleExtensions` / `isBundle` is the single list shared with `AppFilter`; `FinderFolders.hasPathPrefix` compares path prefixes case-insensitively (APFS).

### Disk usage and uninstaller
`DiskUsage.measure/size(of:)` (AppLeftovers.swift) returns `DiskSize` (bytes + `isLowerBound`, `.formatted` gives "≥ 1,2 MB"): counts directories too, never follows symlinks, dedupes hard links (`fileResourceIdentifierKey`), unreadable parts or cancellation set the lower-bound flag; `size(of:)` is async and cancellable (cancel = partial lower bound). `AppLeftovers.locate` (no sizing, case-insensitive names, on-disk spelling, `LeftoverKind` caches/preferences/containers/other) + `findSized` (async, parallel); `find` kept. `GridModel.uninstallPlan(for:)` -> `UninstallPlan` (appSize, leftovers, groups, totals) is the single place that counts sizes for `TrashConfirmationCard` and `UnusedAppsSection`. `moveLeftoversToTrash(of:_:)` trashes only given leftovers (caches-only button); both trash paths re-check URLs through `locate`. Shared Application Support/<name> folders are still deliberately not matched.

### Statistics and shared stats
Statistics: `UsageLog.swift` (`UsageLog`, `UsageLogStore`, `UsageLogger.shared`) keeps `usage-log.json` in the DEFAULT support folder (never the synced one): per day, per bundle ID launch counts, no timestamps, 366 days, an `enabled` flag inside the file. `AppDelegate.observeLaunches` records every launch of a catalog app (10 s dedupe). `UsageReport.make` builds top apps, weekday counts and the last 30 days; `UsageReport.notOpened` is the 90-day rule. `StatsSettingsView` (Settings tab `.stats`, Swift Charts, single accent hue plus printed values) shows it and has the switch and "Стерти".
Shared stats: with a chosen data folder, `SharedStatsFiles.make` (LayoutFileWatcher.swift) puts history.json and usage.json next to layout.json (copying the local ones once). `AppHistory.merged(with:)` (min firstSeen, max lastLaunched/launchCounts, union seen); `AppHistoryStore.isShared` makes `saveHistory` merge with the file first (`loadForMerge()` never quarantines a half-synced file; nil = leave alone, which respects `historyUnreadable`). `UsageStore(deviceID:)` stores `{"devices": {id: UsageStats}}`, `load()` returns all devices combined (`UsageStats.combined`), `save` writes only this Mac's part (diff against the last combined value); a plain legacy file counts as device "legacy". `GridModel.reloadSharedStatsFromDisk()` merges into memory without saving; `SharedStatsWatcher` calls it. Replaces the old rule that usage.json/history.json always stay in the default folder.

### Intents, Spotlight, hotkeys
- Intents (`MenuFoldIntents.swift`): `MenuFoldAppEntity` (id = bundle id), `MenuFoldFolderEntity` (folder UUID), `MenuFoldCategoryEntity` (category id), `MenuFoldProfileEntity` (profile id), each with an `EntityStringQuery` reading the live `GridModel` on the main actor (waits up to 3 s for the first catalog scan after a cold start). Actions: `LaunchAppIntent`, `PinAppIntent`, `UnpinAppIntent`, `AddToFolderIntent`, `AssignCategoryIntent` (nil category = automatic), `SwitchProfileIntent` (nil = no profile); they don't foreground the app. Siri phrases live in code and are translated in `App/AppShortcuts.xcstrings` (the phrase catalog; `${applicationName}` keys in Localizable.xcstrings are stale and not used there). Phrases with a parameter use `${app}`. Keep ≤10 shortcuts.
- Per-item hotkeys: `Layout.appHotkeys` (`AppHotkey{keyCode, modifiers}`, keys "app:<bundle id>" / "folder:<uuid>", validated on load, one combination = one entry; `GridModel.setHotkey(_:forApp:/forFolder:/forKey:)` moves a combination away from its previous owner). `HotKeyManager` (now `@Observable`) registers the main shortcut (id 1) plus one Carbon hot key per entry and follows `model.layout.appHotkeys`; refused ones are in `conflicts` (Settings shows a warning). UI: `AppHotkeysSection` (Settings → Програми) and "Гаряча клавіша…" in the app/folder tile menu (`HotkeyEditRequest` opens Settings on that row). `AppDelegate.handleHotkey(key:)` launches the app or opens the folder (`showPanel(folderID:)`). URL: `menufold://launch?id=`.
- Spotlight: `SpotlightIndexer` (CoreSpotlight, domain `com.menufold.items`) indexes visible folders and custom categories with `contentURL` `menufold://folder?name=` / `tab?name=`; debounced reindex on layout changes, full rebuild at launch; `AppDelegate.application(_:continue:)` handles the Spotlight activity. UserDefaults key `indexesInSpotlight` (default on), Settings → Загальне. Risk: ad-hoc signing gives no stable code identity, so macOS may drop the items after an update; they are rebuilt at every launch. Untested on a real Spotlight index.

### Displays and in-app accessibility overrides
Multi-display: `AppPreferences.panelScreenPolicy` (`PanelScreenPolicy` in Core `DisplayPlacement.swift`: cursor/primary/activeWindow) is resolved by `DockGeometry.targetScreen` (activeWindow = topmost layer-0 CGWindowList window of another app, no Accessibility). `DisplayPlacement.screenIndex` / `fittedGrid` are pure and tested. `DockGeometry.fitGrid` runs in `PanelController.show()`/`resizeIfNeeded` and sets `AppPreferences.fittedColumns/Rows` (not persisted); `GridMetrics` reads `effectiveColumns/effectiveRows`, so the grid shrinks on small screens. Panel collectionBehavior includes `.stationary`.
In-app accessibility overrides: `AppPreferences.forcesReduceMotion/forcesIncreaseContrast` (can only turn ON). `ThemeOverrides.swift`: apply `.themeOverrides()` to the root view, then read `@Environment(\.menuFoldReduceMotion)` / `\.menuFoldIncreaseContrast` (system OR override); AppKit code uses `ThemeOverrides.reduceMotion` / `.increaseContrast` instead of NSWorkspace.accessibilityDisplayShould*. Wired: `PanelController` applies `.themeOverrides()` to the root; views read `\.menuFoldReduceMotion` / `\.menuFoldContrast` (never the raw system keys inside the panel).

### Accessibility
Accessibility: use `Theme.motion(_:reduceMotion:)` or `.themedAnimation(_:value:)` (View extension in Theme.swift, falls back to `Theme.crossfade`) instead of raw `.animation`/`withAnimation`; floating cards use `.cardShadow()`, tile labels `.tileLabelFont()` (semibold under Bold Text). Tiles expose VoiceOver actions (`AppIconView.voiceOverActions`, folder tile `accessibilityActions`) as the alternative to drag and drop; the folder overlay is `.isModal`. Views read `colorSchemeContrast`, `accessibilityDifferentiateWithoutColor` and `accessibilityReduceTransparency` for dots, badges and the selection ring.

Release without CI: while GitHub Actions is unavailable, run `scripts/release.sh` locally and publish with `gh release create`; `scripts/check-localization.py` checks the string catalog (also run by CI).
